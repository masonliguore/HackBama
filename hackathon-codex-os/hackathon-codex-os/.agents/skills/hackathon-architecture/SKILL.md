# Hackathon Architecture

1. Define exact user action, input, processing, output and observable success.
2. Use one frontend plus at most one backend unless a simpler design can work; prefer familiar, deployable defaults.
3. Specify interfaces, local fixture data, failure/timeout states, and independent contract checks.
4. Document real versus mocked API calls; verify third-party limits/terms and credits.
5. Save architecture and run commands to PLAN.md. Reject complexity not necessary to demonstrate the differentiator.
