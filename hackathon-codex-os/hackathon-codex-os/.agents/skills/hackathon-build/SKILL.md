# Hackathon Build

1. State the smallest task and observable acceptance test before editing.
2. Check git status; do not overwrite unrelated edits. Work on one vertical slice.
3. Build, run, and fix only the requested surface. Avoid placeholder buttons unless clearly labeled.
4. Run precise tests, lint/build if available, and a smoke test of the user journey.
5. Document the exact test command, real outcome, known limitation, and update PLAN.md.
